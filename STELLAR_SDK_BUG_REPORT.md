# Stellar SDK React Native Bug Report

## Summary

The React Native version of `@stellar/stellar-sdk@16.0.1` fails to parse valid XDR that contains a 5-character asset code ("RCPHP"), while the Node.js version parses the same XDR successfully.

## Environment

- **Package**: `@stellar/stellar-sdk@16.0.1`
- **React Native**: `0.86.0`
- **Expo**: `~57.0.4`
- **Platform**: Android (tested) / iOS (not tested)
- **Node.js** (comparison): `v22.13.0`

### 3. React Native Fails to Parse XDR ❌

```typescript
// React Native (src/services/stellar-wallet-service.ts)
import { TransactionBuilder } from '@stellar/stellar-sdk';

const transaction = TransactionBuilder.fromXDR(
  pkg.unsignedEnvelopeXdr,
  pkg.networkPassphrase
);
// ❌ THROWS: Asset code is invalid (maximum alphanumeric, 12 characters at max)
```

**Error:**
```
Error: Asset code is invalid (maximum alphanumeric, 12 characters at max)
  at TransactionBuilder.fromXDR (stellar-sdk)
```

## Expected Behavior

The React Native Stellar SDK should parse the XDR successfully, just like the Node.js version does, since:
1. Asset code "RCPHP" is **5 characters** (valid - max is 12)
2. Asset code is **alphanumeric** (valid)
3. **Same XDR parses fine in Node.js**

## Actual Behavior

React Native throws: `Asset code is invalid (maximum alphanumeric, 12 characters at max)`

## Analysis

The XDR hex shows the asset code bytes at position 0x98-0x9D:
```
... 52 43 50 48 50 00 ...
    R  C  P  H  P  \0
```

This is **correct encoding** for a 5-character asset code with null-padding.

## Possible Causes

1. **Buffer polyfill differences** in React Native
2. **XDR parser bug** specific to RN environment
3. **Asset validation logic differs** between Node.js and RN builds
4. **Babel/Metro transformer** corrupting the asset validation code

## Workarounds Attempted

None successful yet. The issue persists across different amounts and fresh QR codes.

## Impact

- **High**: Blocks all payment transactions in production React Native app
- Asset codes 5-12 characters may all be affected
- Only affects React Native, not Node.js/Deno environments

## Related Issues

- Similar to asset validation issues reported in earlier SDK versions
- May be related to React Native's lack of native Buffer support

## Requested Fix

Please ensure the React Native version of the Stellar SDK:
1. Uses the same XDR parsing logic as Node.js
2. Properly handles Buffer/Uint8Array conversions
3. Validates asset codes consistently across environments

## Additional Context

- XDR was generated by Deno Edge Function using same SDK version
- Invoice validation passes on server side
- Asset code "RCPHP" is used for a real testnet asset
- Issuer: `GBC6HZTIUH6C3KQR5D3NOS2PJ7YKQJQNAQGAO3WO4PICJEXPAPGRKSQ7`
